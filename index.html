Bloco 2

Exemplos de prompts que funcionam melhor

Prompts curtos, com objetivo + contexto + formato de saída.

Marketing

Transformar planilha em plano de dashboard

Peça análise, KPIs, lacunas e layout recomendado para o dashboard.

prompt pronto
Analise esta planilha de marketing. Identifique métricas principais,
dimensões úteis, anomalias, e proponha um dashboard executivo com
6 cards, 3 gráficos e uma tabela final. Responda em tópicos e diga
quais colunas estão faltando.
Customer Success

Ler base de clientes e sugerir priorização

Ótimo para churn, health score, playbooks e segmentação de acompanhamento.

prompt pronto
Leia esta base de customer success e classifique os clientes em risco,
atenção e saudável. Proponha um health score inicial, explique as
regras e monte um plano de ação semanal para o time.
Banco de dados

Começar um modelo relacional simples

Ideal quando você ainda está saindo de planilhas e precisa estruturar tabelas.

prompt pronto
Com base nesta planilha, proponha um desenho inicial de banco de dados.
Separe entidades, chaves primárias, relacionamentos e campos
obrigatórios. Depois escreva um SQL inicial de criação das tabelas.
Bloco 3

Skills e hábitos que mais aceleram iniciantes

Aqui, “skills” significa repertório operacional e instruções reutilizáveis.

As 5 skills mentais mais úteis no começo

  • Contexto antes de solução: peça primeiro um resumo da base, depois a execução.
  • Saída estruturada: sempre defina o formato: tabela, checklist, SQL, plano em etapas.
  • Validação explícita: peça para apontar lacunas, riscos e como testar.
  • Iteração curta: uma tarefa por vez; evite “faça tudo” em um único prompt.
  • Reuso: salve prompts bons como modelos internos do seu time.

Pacotes de uso recomendados

  • Resumo de planilhas
  • Desenho de dashboards
  • Classificação de clientes
  • Leitura de CSV
  • Modelagem SQL inicial
  • Checklist de qualidade
  • Playbook de onboarding
  • Prompt de revisão final
1

Primeiro peça leitura

Ex.: “leia esta pasta / planilha e me diga como está organizada, o que falta e quais perguntas devo responder primeiro”.

2

Depois peça transformação

Ex.: “agora transforme isso em um dashboard executivo / health score / estrutura SQL”.

3

Por fim peça verificação

Ex.: “liste os riscos, premissas e como validar se a solução faz sentido antes de eu publicar”.

Bloco 4

Mini labs para validar o conhecimento

Cada lab tem objetivo, prompt inicial e o que você deve checar.

Lab 1 • Marketing

Dashboard a partir de planilha

Pegue um CSV com campanhas, canais, leads e custo. Faça o Claude Code propor um dashboard para liderança.

prompt inicial
Analise este CSV de marketing e proponha um dashboard para liderança
com KPIs, filtros, gráficos e alertas. Também diga quais métricas são
de vaidade e quais são acionáveis.
  • O dashboard separa aquisição, conversão e custo?
  • Há sugestão de filtros por canal, período e campanha?
  • O Claude apontou colunas ausentes?
Lab 2 • CS

Health score de clientes

Use uma planilha com clientes, logins, tickets, MRR e NPS para testar uma classificação simples.

prompt inicial
Com esta planilha de clientes, crie uma primeira versão de health
score. Explique pesos, faixas de risco e um plano de ação para contas
críticas nos próximos 7 dias.
  • As regras são explicadas de forma legível?
  • Há categorias claras de risco?
  • Existe plano de ação e não apenas diagnóstico?
Lab 3 • Dados

Primeiro passo para banco de dados

Saia de uma planilha única para um desenho relacional inicial com SQL de criação.

prompt inicial
Pegue esta planilha e desenhe um banco relacional inicial. Defina
tabelas, relacionamentos, chaves e escreva um SQL base para
PostgreSQL.
  • As entidades foram separadas de forma lógica?
  • Há PK/FK consistentes?
  • O SQL é utilizável e não apenas conceitual?

Roteiro de 15 minutos para um iniciante

Use este roteiro para testar se a pessoa realmente entendeu o básico.

A

Minuto 1–3

Instalar, rodar claude --version e abrir um projeto com claude.

B

Minuto 4–7

Pedir um resumo de uma planilha ou pasta real e conferir se o modelo entendeu o contexto.

C

Minuto 8–11

Pedir uma transformação: dashboard, health score ou SQL inicial.

D

Minuto 12–15

Fechar com validação: “quais riscos, premissas e próximos testes você recomenda?”
